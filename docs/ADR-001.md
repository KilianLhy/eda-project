# ADR-001 : Choix de stack NestJS + Next.js

## Statut

Accepté

## Contexte

Le projet doit livrer rapidement une API, une UI Kanban minimale, des tests unitaires et une architecture hexagonale. L'équipe a besoin d'une stack TypeScript homogène pour limiter le cout cognitif pendant les disruptions. Le repository de cours fournit des exemples orientés NestJS/Next.js.

## Décision

Nous avons décidé de construire le backend avec NestJS et le frontend avec Next.js (App Router), en TypeScript sur les deux couches.

## Alternatives envisagées

| Alternative | Raison du rejet |
|-------------|-----------------|
| Spring Boot + React | Plus verbeux pour ce sprint court et moins aligné avec les exemples fournis. |
| FastAPI + Next.js | Rupture de langage entre backend et frontend. |

## Conséquences

**Positives :**
- Productivité rapide pour les modules project/task et les tests.
- Forte lisibilité de la séparation domain/application/infrastructure/presentation.

**Négatives / compromis :**
- Dépendance à l'écosystème Node.
- ORM PostgreSQL non branché en phase 1, repository en mémoire pour privilégier le domaine.

**Points de vigilance :**
- Introduire l'adaptateur ORM PostgreSQL en phase 2 sans toucher les services métier.
